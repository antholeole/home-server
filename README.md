This is my tiny home server! It uses k3s and nixos.

- Services are exposed to the internet using cloudflare tunnels.
- Custom containers are built using nix-snapshotter.
- In general, any cloud infra is cloudflare - DNS, domains, etc.
- Colmena, nixos anywhere, and disko are used for hardware management.
- Secrets are stored in this repo, under either sops-nix or sealed-secrets,
  depending if we need them at build time for nix modules or if we can get away
  with decrypting them at runtime as a kubernetes secret.

It runs on small lenovo server. The frontend is a surface go running KDE
plasma. I do have a second node ready to be stood up, but I have no reason to
have the extra power draw currently since I'm only running a single service.

## Using

The below instructions assume that you are me; that is, all the configuation
of your devices are exactly the same - you should read this disclaimer as "this
repo is useless unless you change all the constants first". These constants
reside in `ssot.nix`.

## Bootstrapping a node

`nixos-anywhere` was not designed to work over wifi; so this process is a bit
busted. Some manual work is required, it isn't quite headless. This
documentation is mostly for myself - I wouldn't expect this to be very helpful
for others, unless they copy my exact setup.

1. Generate an iso with `nix run .#make-iso`. This will inject the encrypted
   secrets from your nix store along with the master key at
   `~/.secrets/id_ed25519` - the master key is copied in with a `cp` rather than
   as a nix object, since we don't want secrets in the nix store.
1. Format a drive with the iso using `dd`, enter BIOS and boot the iso.
1. The device should show up in an `arpscan` - the iso is pre-configured to
   connect to my wifi with a wifi password, so this step should be seamless (for
   me!).
1. Create a config in `./hosts/<device>/default.nix`. the flake-module
   `disk-efi` contains a disk config, and `boilerplate` contains some helpful
   utilities like `btm` and `kak` along side the wifi password, so those are
   helpful as well.
1. `nixos-anywhere --generate-hardware-config nixos-generate-config \
./vm/devices/<device>-hardware-config.nix --flake .#<device> root@<device ip>`
   will format the disk and generate you the hardware config.
1. add the device to `default.nix` as a colmena device. Then, rekey the
   secrets using `agenix-rekey`; this will add the private ssh key of the
   server as a decryptor of the secrets, wifi password included.
1. rekey the secrets.
1. `colmena apply --all` to re-upload the newly keyed devices to all systems.
1. Voila! reboot the system without USB and enjoy your nixOS install.

Colmena will manage the systems from then on.

## what isn't reproduceable

First of all, I'm fairly certain the above steps aren't perfect. I did it
twice, and both times I had to wing some of the process - as I add more nodes
I will refine the process.

Second, all the sealed secrets depend on the certs generated by k3s itself,
so if bootstrapping a new cluster, each of the secrets in `lib/sealed.nix` need
to be regenerated.

Besides having to redo all the variables in `ssot.nix`, everything else should
be reproduceable. 

## Developing

The iso can be ran in qemu if desired; to develop on it, run the `run-iso` app
(the first arg is a path to the output of your above `make-iso`). Then, you can
ssh into it with `ssh localhost -p 2222 -l manager`, provided you have
configured it with the correct public keys - i.e. the ones that correspond to
the machine issuing the command. Its now a valid nixos target, so you may
iterate without the physical devices as you wish:

`nixos-rebuild switch --use-remote-sudo --build-host localhost --target-host localhost:2222 --flake ".#<flake-role>"`
